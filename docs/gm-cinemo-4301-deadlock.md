# GM / Cinemo 车机（凯迪拉克）连不上：0x4301 死锁与修法

> 分析对象：`CarDeck-log-20261023-230404.txt`（CarDeck 0.1.13-debug，OnePlus PJZ110 / Android 17）
> 车机：`CADILLAC_7731` / model `A2LL` / SA8155 / **Cinemo 组件栈** / manufacturer General Motors
> 结论日期：2026-10-26。上游同族修复：shaonialife/cardeck **PR #19**（CT5，2026-10-23 合并）

## 1. 一句话结论

蓝牙 iAP2 这一层**全部打通**（识别、鉴权、问候、0x4300 都成功），卡在「车机一直不给热点凭据」：

- 车机能力清单里**没有 0x5702/0x5703**（旧协议 WiFi 配置交换），所以手机拿不到 SSID/密码；
- 车机声明会发 **0x4301**（新协议，AP 信息随它下发），但窗口内**一条都没发**；
- 而 0x4301 的发出前提是「车机在自己的 Wi-Fi 网段里发现手机的 `_carplay-ctrl._tcp` 并发邀请」——
  手机没有凭据进不了车机网络，车机看不到手机就不发 0x4301，**双方互等**。
- 旧实现窗口一到就 `throw IOException` 拆链重连，每轮都把车机侧刚积累的状态清零，
  于是变成「6 轮循环、车机始终静默」的稳定失败。

## 3. 为什么 0x4301 不来

`CinemoWIFIComponent` / `CinemoBTComponent` 这两个组件说明车机的 CarPlay 由 Cinemo 栈提供。
同族车机（CT5/A2LL）的实测结论：

1. 真 iPhone 连的是车主热点（如「全新CT5」），并且**忘掉该网络后仍能无线连上** →
   车机确实会经蓝牙把凭据推给手机，0x4301 会发，只是**晚发或等前置条件**；
2. 奥迪 MMI 9310 先例：Phase 1 结束后 **2 分 35 秒**才补发 0x4301；
3. 手动让手机先连上车机热点后重跑，旧版本仍失败——因为旧流程在拿到端点之前就拆链了，
   根本没走到「在车机网络里广播 ctrl → 车机邀请 → 0x4301」这一段。

所以这是**时序/前置条件**问题，不是协议字段写错。

## 4. 修法（本分支 `bieke`，移植上游 PR #19）

`iap2/Iap2SenderSession.kt`

- 车机声明会发 0x4301、但窗口内未到时**不再抛异常拆链**：返回 `ssid=""` 的空端点，
  链路进入保活；晚到的 0x4301 由 `pumpIncomingForever → handleLateStartSession →
  onEndpointUpdate` 重新触发完整配对。
- 空端点**不缓存空 wifi**：否则保活期 `parseStartSession` 的 `ap = wifi ?: fromSession`
  会用空凭据覆盖晚到 0x4301 自带的 AP 信息，把唯一凭据来源丢掉。
- 车机**没声明**会发 0x4301（且无凭据）时，仍然抛异常——继续等只会空转。

`SessionController.kt`

- `onCarPlayEndpoint` 收到空端点 → 记日志、`phaseHint="等待车机下发连接信息（0x4301）…"`、
  **不占 `sessionStarting`**（晚到端点要走「上一轮已结束」分支），转入等待观察。
- 新增 `watchForPendingStartSession`：每 5s 查一次手机当前 WiFi；
  用户手动连上车机热点后弹「按车机热点继续 / 继续等待」，确认即用该 SSID 合成端点
  重走 `onCarPlayEndpoint`（无端口 → mDNS/网关兜底，复用现成代码）；
  同一 SSID 只问一次、换网络再问；`PENDING_START_SESSION_WAIT_MS = 5 分钟` 无进展才拆链。

## 5. 实车复测怎么判读

连车机后看日志（任一条出现即为进展）：

- `iap2 0x4301 窗口内未到但车机声明会发——不拆链，返回空端点进入保活` → 新行为生效；
- `>>> [..] 端点无 AP 信息（车机未在窗口内下发 0x4301）——…等待晚到 0x4301` → 进入等待态；
- `iap2 rx=0x4301 …`（保活期） → **晚发假设成立**，后面应自动入网出画面；
- `检测到已连接 XXX` 弹窗 → 手动入网路径可用，选「按车机热点继续」；
- `空端点等待 5 分钟超时` → 两种假设都不成立，需导出完整日志（等待期 Wi-Fi 状态、
  是否有 ctrl 邀请 `GET /ctrl-int/1/connect`、mDNS 是否发现 `_airplay._tcp`）。

## 6. 仍未解决的部分

- 若车机的 0x4301 真的要求「手机已在它网络里」且**必须先有凭据才能入网**，
  那就只能靠用户手动入网（车主在车机设置里能看到热点名/密码）——本分支已把这条路做成引导。
- 手动入网后 mDNS 广播是否走在车机那个网络接口上，取决于 Android 的默认网络选择；
  若日志显示已入网却 `mDNS 未发现 _airplay._tcp`，下一步要查 `bindProcessToNetwork` 与组播出口。
